PhaseWeaver Agent 执行运行时 v0.1 · 2026-11-07 GitHub

把 Agent 的工具阶段
变成可编程的显存决策

位于编排层与推理引擎之间的执行运行时

它看见 Agent 在「推理 ↔ 工具 ↔ 等待」之间的切换,把 KV Cache 的处置 (保留 / 卸载 / 丢弃 / 释放)变成显式决策;父子 Agent 之间以所有权移交消除重复 prefill。 数据来自 [L1] 确定性仿真,尚未在真实 GPU 上验证。

1问题:工具阶段,GPU 在等

同一时刻只有一条推理流在算,但两条轨迹的显存都被占着。

2架构:三层,一个契约

Agent 只管阶段,运行时管资源,引擎管计算;契约只有 reason / call_tool。

3一次回合:谁在什么时候做什么

推理与工具交替;显存决策发生在阶段切换的瞬间。

4状态与不变量:没有“占着显存却没有租约”

执行阶段与 KV 归属正交;每次状态变更后检查七条不变量。

5KV 移交:子从父的上下文继续

默认子要重新 prefill 整段上下文;移交把这笔开销变成零。

6结果:交接在结构化场景是数量级收益

2 GiB · 3 seeds · 确定性仿真 [L1];数值标注在图上。

7边界

仅仿真证据真实 GPU 适配器已实现,但 L3 实测缺失(issue #3)。
autopilot 非最优安全默认,不是每个场景都赢;系统暴露的是策略组合。
已知技术债租约容量等待仍是轮询;多机调度不在范围内。
