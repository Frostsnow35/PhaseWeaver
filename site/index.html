PhaseWeaver Agent Execution Runtime v0.1 · 2026-11-07 GitHub

Make the tool phase
a programmable memory decision

An execution runtime between agent orchestration and the inference engine

PhaseWeaver watches an agent move between reasoning ↔ tools ↔ waiting and turns KV-cache disposition (retain / offload / drop / release) into an explicit decision. Between parent and child agents, it makes ownership transfer eliminate repeated prefill. All numbers are [L1] deterministic simulation, not real-GPU measurements.

1Problem: the GPU waits during tool calls

Only one stream computes at a time, yet both trajectories hold their memory.

2Architecture: three layers, one contract

Agents expose phases; the runtime owns resources; the engine owns compute. The contract is just reason and call_tool.

3One turn: who decides, and when

Reasoning alternates with tool calls; the memory decision happens at the phase boundary.

4States and invariants: no residency without a lease

Phase and KV ownership are orthogonal; seven invariants are checked after every transition.

5KV handoff: the child continues from the parent

By default a child re-prefills the whole context; handoff turns that cost into zero.

6Results: handoff pays off by an order of magnitude on structured work

2 GiB · 3 seeds · deterministic simulation [L1]; values are printed on the charts.

7Limits

Simulation onlyReal-GPU adapters exist, but L3 measurements are still missing (issue #3).
autopilot is not optimalA safe default; it does not win everywhere, so the system exposes a policy portfolio.
Known debtLease-capacity waiting still polls; multi-node scheduling is out of scope.
