Agent Execution Runtime

把 Agent 的阶段切换,
变成 GPU 资源决策。

Agent 在「推理 ↔ 工具 ↔ 等待」之间来回切换。工具阶段 GPU 空转,显存却被闲置占用。 PhaseWeaver 是一个执行运行时:它看见阶段切换,用处置权租约 决定保留 / 卸载 / 丢弃 / 释放,并在父子 Agent 之间原子移交 KV Cache。

01

问题:不是算力不够,是算力在等

一个典型 Agent 回合是「推理 3 秒 → 工具 30 秒 → 再推理」。工具执行期间 GPU 完全空闲, 但该 Agent 的 KV Cache 仍占着显存,后面的 Agent 只能排队。

推理流(A) 推理流(B) 工具阶段 GPU 实际利用率

两组 Agent 的工具阶段错开时,GPU 利用率反而更低——因为工具期间占用的显存没被让出, 其他 Agent 无法把推理填进空隙。PhaseWeaver 的切入点就在这里。

02

设计:三层正交,一个契约

运行时不是编排框架。它只要求 Agent 通过 unit.reason() / unit.call_tool() 暴露阶段,其余资源决策全部由运行时接管。

正交状态机

Phase × ContextState

执行阶段(PENDING…COMPLETED)与 KV 归属(NONE…HANDED_OFF)是两个独立维度。 七条不变量可断言:任何“占显存却没有租约”的状态都会被测试抓住。

处置权租约

RETAIN / OFFLOAD / DROP / RELEASE

租约表达的是“处置权”,不是“已分配”。引擎能力不足时显式降级 (OFFLOAD → DROP)并记录 degraded_from,不假装支持。

核心创新

父子 Agent 的 KV 移交

fork 时父把 KV 所有权交给子,子零 prefill 起步;join 时交回。 移交是单次不可中断的原子操作:引擎移动 block 与租约转移同步完成。

引擎调用是唯一的挂起点;之后租约、句柄、上下文状态在同一段同步代码内完成转移。

# 父单元:把 KV 交给子,子从父的上下文继续
await unit.reason(prompt_tokens=4096, out_tokens=128)
await unit.fork("researcher", child_fn)   # 默认 handoff
await unit.reason(prompt_tokens=6400, out_tokens=128)

# profile 决定默认继承模式;可显式覆盖

05

边界:哪些结论成立,哪些还没有

这个项目目前的全部性能数字来自确定性仿真。诚实标注比漂亮数字重要。

尚未在真实 GPU 上验证

vLLM / OpenAI 兼容适配器已实现,但 L3 实测缺失(issue #3)。本页任何加速数字都不得当作真实引擎性能。

autopilot 不是万能最优

它是安全默认:所有场景零失败、SLO ≥ 0.94,但编码场景会略逊于基线;B2 在检索场景更好。

已成立:交接的结构化收益

两种拓扑(扇出 / 嵌套)、多 seed 零失败;重算量下降 25%–52%,延迟尾部下降 20%–33%。

已成立:工程可复现性

同 seed 两次运行指标逐位一致;109 测试、mypy 双平台、ruff、6/6 交付闸门全部通过。
