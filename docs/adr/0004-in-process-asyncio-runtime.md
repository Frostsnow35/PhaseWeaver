# ADR-0004:进程内 asyncio 运行时,而非 sidecar

- 状态:已接受
- 日期:2026-11-07

## 背景

三条路线:(A) 进程内 asyncio 运行时库;(B) 独立 sidecar 守护进程 + RPC;(C) 作为 LangGraph / Agents SDK 的中间件。

- B 隔离性最好、最像基础设施,但第一阶段要把协议、生命周期、部署全部做出来,核心机制验证被推迟一倍以上工作量。
- C 代码最少,但拿不到工具进程的取消/回收权,也拿不到子 Agent 的 fork/join 时机——而这两点恰是本项目的主张所在。
- 开发机无 NVIDIA GPU,仅有 CPU 与 16 GB 内存,因此第一阶段必须能在纯 CPU 上跑通完整机制。

## 决定

采用 A:单进程 asyncio 运行时库,工具以受监管子进程执行。
在接口层保留 transport 缝:`runtime.py` 不假设调用方与自己在同一进程——所有对外 API 只依赖可序列化参数与 `await` 语义,未来可通过一层 RPC 暴露为 B。C 作为后续独立 shim 包(约 200 行)实现,不进核心。

## 后果

- 正面:本机 CPU 可跑通完整机制并产出 L1/L2 数据;垂直切片最快;调试链路最短。
- 负面:单进程故障域;Python GIL 下重 CPU 工作会阻塞事件循环(规避方式:工具一律走子进程,仿真用虚拟时钟不空转)。
- 约束:核心模块不得依赖进程内全局可变状态(除 `Runtime` 实例),以保留未来拆进程的可能。
