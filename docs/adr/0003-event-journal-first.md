# ADR-0003:第一阶段即引入事件日志

- 状态:已接受
- 日期:2026-11-07

## 背景

第二阶段是 Durable Agent Runtime:事件日志、检查点、工具结果核对、故障恢复。若第一阶段用可变的运行时计数器与内存指标,第二阶段需要把整个状态管理重构一遍。

## 决定

第一阶段即引入 append-only JSONL `EventJournal`,作为唯一事实来源:
- 每次状态变更写一条事件,带单调 `seq` 与 `cause_seq` 因果链;
- 所有指标由 `MetricsReducer.replay(journal)` 计算,运行时**不维护**并行的可变计数器;
- 第二阶段只需在日志之上增加 `(last_seq, snapshot)` 检查点与工具幂等回执,不改内核。

## 后果

- 正面:指标与行为天然可复现、可审计;mock 仿真的确定性可以用 `journal_digest` 断言;M5 的接入成本降到"加一层"。
- 负面:每个状态变更多一次序列化开销;事件类型成为需要版本管理的契约(新增事件必须登记到规格 §10 的表)。
- 约束:禁止在 runtime 中写"仅内存、不落日志"的状态突变;若确需高频计数器(如队列深度),必须由引擎事件派生而非自行累加。
