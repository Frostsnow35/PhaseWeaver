# 实验记录(v2:F1–F4 之后)

> 全部为 **L1(机制证明)/ L2(参数敏感性)**,mock 仿真,非真实 GPU 测量。
> 环境:Windows 11 / i5-1340P / 16 GB / 无 NVIDIA GPU;虚拟时钟。

## 0. 这一轮修了什么

| 编号 | 问题 | 修复 | 结果 |
|---|---|---|---|
| F1 | 租约 resize 时"先释放后申请"造成窗口期,引擎块数超出预算 | `LeaseBroker.resize()` 原子调整;常驻尺寸提前预留;任务结束同时释放引擎 block | 12 并发下不再出现 `EngineOutOfMemory`(除已知 K1) |
| F2 | mock 只对显存建模,没有算力竞争 | 共享吞吐模型:`rate = base / (1 + α·(n-1))`,α=0.15 | 并发越多单流越慢,首次出现真实的"让位 → 别人变快"通道 |
| F3 | `allow_restore` 误用了 park 冷却,导致等待者饿死 | 冷却只作用于 park;恢复只受容量限制 | 12 Agent 下 B2 完成数 8→12 |
| F4 | 主指标 `idle_waste` 恒为 0 | 新增 `kv_waste`(上下文占用显存但其所有者不在推理的 字节·秒) | 首次出现可区分策略的非零指标 |

## 1. E1 容量匹配场景 [L1]

命令:

```
python -m phaseweaver.demo compare --workload examples/workloads/w1.toml --capacity-gib 4 --policies B0,B1,B2a,B2
```

负载:W1,8 Agent × 4 轮,context 8192 tok 起每轮 +128,tool lognormal(P50=2 s),λ=0.5/s,SLO=120 s,容量 4 GiB,seed=7。

| 策略 | 完成 | SLO | goodput | p50 | p95 | p99 | thrash | 重算 token | kv_waste |
|---|---|---|---|---|---|---|---|---|---|
| B0 全保留 | 8 | 1.000 | 0.1494 | 47.3s | 48.3s | 48.5s | 0 | 0 | 31677 |
| B1 TTL 驱逐 | 8 | 1.000 | 0.1547 | 48.4s | 49.5s | 49.7s | 0 | 0 | 30268 |
| B2a 局部让出 | 8 | 1.000 | 0.1386 | 50.9s | 54.5s | 54.9s | 14.55 | 169472 | **9257** |
| B2 全局 SLO | 8 | 1.000 | 0.1419 | 50.0s | 52.6s | 53.6s | 7.45 | 110208 | **16430** |

结论(如实):

1. **F4 指标成立**:B2a 把"占用但不推理"的浪费压到 B0 的 **29%**,B2 压到 **52%**。这是本项目第一次拿到方向正确的量化证据。
2. **F3 生效**:B2 的 thrash 是 B2a 的一半(7.45 vs 14.55),重算量也少 35% —— 防抖旋钮确实在起作用。
3. **仍然没有吞吐收益**:容量匹配时没有排队,让出显存没有让任何请求变快,反而让 p50 慢了 6%、goodput 低 5%。这与规格 §12.4 的判据一致地"不成立"。

## 2. 队列场景(K1:已知缺陷)

把 agents 提到 12(容量只够 8~9)时,**B0/B1 会把虚拟时钟拖到 600 s 以上甚至挂住**,B2/B2a 则能完成 12/12(SLO 1.0)。

- 现象:`_sync_lease` 等待容量时,`VirtualClock` 的空闲跳跃启发式被"等待者反复续约定时器"破坏,时钟推进异常缓慢。
- 已做的缓解:等待改为 `LeaseBroker.wait_for_capacity()` 事件驱动,不再轮询时钟。
- **仍未解决**:12 Agent 的 B0 跑不出结果(>120 s 真实时间未结束)。因此本轮所有表格都基于 8 Agent(容量匹配)场景。
- 影响面:只影响"队列始终非空"的过载实验,不影响机制正确性(测试全绿)。

## 3. 当前可信结论与不可信结论

可信:

- 让出策略能把"显存被闲置占用"降低 2–3.4 倍(指标本身经过口径修正)。
- 防抖参数显著降低 park/restore 抖动与重算量。
- 在容量匹配负载下,让出是**纯成本**,不应默认开启。

不可信 / 尚未验证:

- 过载下的吞吐与尾延迟对比(K1 阻塞)。
- B2 vs B2a 在高并发、非均匀 SLO 下的优劣。
- 任何真实 GPU 行为(L3 完全没有)。
