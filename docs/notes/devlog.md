## 方向校准(截至 v8)

**在做的事**:一个位于 Agent 编排层与推理引擎之间的运行时。它把 Agent / Subagent / 工具调用
看作可管理的执行单元,在"推理 ↔ 工具 ↔ 等待"的阶段切换点上,以**租约 + 处置策略**协调
推理侧的 KV Cache(保留 / 卸载 / 丢弃 / 释放),并保证子 Agent 树与失败路径上的资源不泄漏。

**目前有证据的**:

| 主张 | 证据强度 | 备注 |
|---|---|---|
| 让出策略能显著减少"占用但不推理"的显存浪费 | L1/L2,3 seeds | 2 GiB 下 kv_waste −48% |
| 过载时能同时改善 SLO 达成率与 p99 | L2 | 2 GiB:SLO 0.972→1.000,p99 −6% |
| 子 Agent 扇出时父单元让位带来收益 | L1 | p99 −23.7%,goodput +22.8% |
| 隔离配额 + 上下文压缩能限制爆炸半径 | L1 | 贪婪子场景 SLO 1.000 vs 0.875 |
| 容量充足时策略自动退化、零开销 | L1 | 8 GiB 与 B0 完全一致 |

**目前没有证据的**:真实 GPU 行为(L3)、最优性间隙(K6 未修)、成本模型(K3 负结果)。

**明确不做**:重写推理引擎、分布式调度、Web UI、真实浏览器自动化、RL 调度器。
**不做 M5 的理由反面**:M5(vLLM/OpenAI 适配器)不是"重写引擎",它是把"引擎无关"这句
架构承诺变成可执行代码;且**可以用本地假 OpenAI 服务验证**,不需要 GPU。所以下一步做它。

## 2026-11-07 · 会话 9:KV 继承(KV fork)与创新性定位

- 新增 `docs/notes/positioning.md`:明确 P1(子 Agent 树的资源语义)是最强差异化、P2(处置权租约+
  能力协商)是次强,并列出**不能声称**的三条(避免与 Tokencake 撞车)。
- 实现了新原语:**KV fork**——子单元引用父单元的 KV 前缀,只为自己新增的 delta 付显存与 prefill。
  新增 `prefix.py`(引用计数前缀组)、`Lease.charged`(组只计费一次)、mock 后端按 delta 分配 block。
  单测覆盖:组引用计数、前缀只计费一次、delta 计费、释放归零(4 个用例通过)。
- **集成未完成**:运行时在"反复 acquire/release + resize"的路径上会让组计费重复累计,
  触发 `I3 used > capacity`。因此 `inherit_prefix` 默认 **False**,w7 两个工作负载仅作实验留档。
  结论:**原语可用,接线未完成**,不能作为成果数字引用。
- 教训:共享计费的正确性不在单测,而在"生命周期与失败路径"上;下一步要么改成显式 handoff
  (不引入组),要么给每个 (unit, group) 建独立引用对象并让 broker 在 release 时做对账。

## 2026-11-07 · 会话 10:K12 用显式 handoff 重做 KV 继承(打通)

- 放弃引用计数方案,改为**所有权移交**:`backend.handoff(handle, new_unit, new_ctx)` 移动
  block 归属;父上下文进入新状态 `HANDED_OFF`(无驻留、无租约),join 时交回并通过
  `_pending_adopt` 在父的下一次 `reason()` 零重算恢复。
- 两个关键缺陷:
  1. 状态机缺 `RETAINED → HANDED_OFF`(父在 park 后仍持有 KV 时就交接);缺这条会直接 FAILED。
  2. 交接后父的租约必须释放,否则 I2/I3 都会错。
- 结果(W8,2 GiB,3 seeds):goodput **+9.7%**,p99 **−10.1%**,重算 **−28.7%**,零失败。
- 结论:这是目前**唯一没有邻居**的机制,且已能产出数字。默认仍为关闭(`inherit_prefix=False`),
  通过工作负载显式开启,避免扰动历史实验。

## 2026-11-07 · 会话 11:K12b 扇出交接与 copy 模式

- 把 `inherit_prefix: bool` 升级为 `inherit_mode: none | handoff`(copy 试过即弃)。
- **copy 模式失败的教训**:复制前缀只是把问题从"重算"搬到"准入"——2 GiB 下 9 个任务失败 5 个。
  结论:在没有 KV 共享原语(如 block 级 refcount)时,复制不是解法。保留在代码注释里,不再暴露。
- 扇出实验结果(none vs handoff,p99 142.6→90.9 s,goodput +49.6%),但 SLO 从 1.000 掉到 0.958:
  交接让第一个子跑得更快,却把其他兄弟挤到更晚——**局部最优不等于全局最优**,和 K3 的教训一致。
- 下一步:要么把 handoff 扩展为"接力链"(每个子依次接管),要么接受"只交接第一个"并在调度上
  优先放行已接管的子。前者改语义,后者改调度,需要先想清楚再动手。
