# 战略 v2:先可比,再差异化

- 日期:2026-11-08
- 取代:`2026-11-07-runtime-roadmap.md` 中的 R1–R7 排序(该文件保留为历史记录)
- 一句话:**不比最快更快,但比最快更不会坏。** 前提是先在真机上做到"不比最快慢"。

## 0. 为什么要改

当前仓库在"语义层"(租约、不变量、原子移交)是扎实的,但同类工作已经占住了真正被评估的位置:

| 能力 | 领先方 | 我们的现状 |
|---|---|---|
| 真实 GPU 数字 | KVFlow / Continuum / SAGA / Llumnix | 只有 `[L1]` 仿真 |
| KV 预取与传输重叠 | KVFlow | 无 |
| TTL 保留策略与鲁棒性 | Continuum | slack/cooldown 启发式 |
| 引擎内 KV 控制(pin/flush/offload) | SGLang HiCache / vLLM | 仅 HTTP 适配器,无法强制 park |
| 程序级/集群调度 | Autellix / SAGA / Llumnix | 单节点准入 |

结论:如果继续投入在语义层,产出的是"设计上更优雅、评估上不可比"的工程。**必须先补齐可比性,语义只作为差异化保证存在。**

## 1. 取舍清单

### 停止投入(明确砍掉)

- 多机/集群调度、跨实例 live migration(对手已做且需要集群资源)
- 程序级公平性理论、Bélády 类最优性证明
- 相位对齐与类似的调度启发式(已有负结果,不续)
- 插件生态扩张、站点与文档继续打磨
- 新增不变量/状态机精修(现有 7 条够用)
- 大而全的 profile/场景库

### 必须补齐(不做就无法被认真比较)

1. **引擎内 KV 控制**:在 SGLang(首选)或 vLLM 上实现 `retain / park / drop` 三个原语
2. **预取**:park 后主动 CPU→GPU 预取,与计算重叠
3. **TTL 保留**:把 Continuum 式 TTL 作为 `RETAIN` 的一个策略实现,作为基线也是能力
4. **真机基准**:单卡、可复现脚本、三个指标(TTFT p99 / JCT p99 / 重算 tokens)
5. **故障注入**:取消、工具超时、引擎 stall、租户配额耗尽

### 保留但不作为卖点

- 租约与不变量 → 只用于"故障下零泄漏、配额不串扰"的实验,不写进主叙事
- 确定性仿真 → 作为快速 A/B 与回归工具,不替代真机结论

## 2. 目标与判定

**主目标(单一)**:在单机、单引擎、工具密集的多 Agent 负载上:

- 正常路径:JCT p99 与 TTFT p99 对比 SGLang+HiCache **不劣化超过 5%**
- 故障路径(取消/超时/stall/配额):**资源泄漏 = 0**,受影响租户 SLO 下降 ≤ 2 个百分点,恢复时间 ≤ 1 次调度周期
- 差异化指标:故障场景下 JCT 优势 ≥ 20% 或 SLO 优势 ≥ 10pp

**判定为失败的条件(触发即停)**:

- P1 结束时正常路径仍落后 HiCache > 10% → 停止"更快"路线
- P2 结束时故障注入无法带来可测的 SLO/泄漏优势 → 转工具化定位(见 §5 备选)
- 两周内拿不到可用的 24GB+ GPU → 降级为"仿真 + 单卡云实例半真实",明确标注,不冒充 L3

## 3. 三阶段

### P0(1–2 周):真机最小闭环

- 选定引擎:SGLang(有 radix cache、HiCache、flush 语义,便于挂 hook)
- 实现三个原语 + 一个 workload 跑通;定义 baseline(SGLang / +HiCache / TTL 模拟)
- 产出:一张真机表(3 指标 × 3 配置),脚本可复现
- Gate:数字能跑出来,且我们能解释每个差异来源

### P1(3–5 周):追平基础项

- 预取与计算重叠、TTL 保留、批内准入
- 产出:与 HiCache 打平(±5%)的对比表 + 消融(预取/TTL/准入各贡献多少)
- Gate:正常路径达标,否则停止

### P2(5–8 周):故障与隔离差异化

- 四种故障注入 × 三个租户配额场景
- 产出:泄漏计数、SLO 降幅、恢复时间;对比 HiCache/无运行时
- Gate:达到 §2 差异化指标,否则转备选定位

## 4. 实验设计

- 模型/硬件:Llama-3.1-8B 或 Qwen2.5-7B,单卡 24–80 GB
- 负载:工具密集 Agent(代码测试/浏览),上下文 4–16k,并发 8–24,任务 2–5 分钟
- 基线:SGLang、SGLang+HiCache、TTL-pin(Continuum 简化版)、KVFlow(若可复现)
- 指标:JCT p50/p99、TTFT p99、SLO 达成率、重算 tokens、显存利用率、泄漏/孤儿进程数、恢复时间
- 故障:工具进程被 kill、工具超时、引擎 stall 5 s、租户配额打满、取消风暴
- 证据等级:真机标 `[L3]`;仿真只作补充,不混表

## 5. 风险与备选

| 风险 | 备选 |
|---|---|
| SGLang 内部接口变动大、patch 维护贵 | 改走 LMCache/`KVConnector`;或退到 vLLM sleep/offload 能力 |
| 无真机 | 云单卡按小时租用;再不行降级为 `[L2]` 半真实并明确标注 |
| 正常路径打不平 | 承认"工具化定位":确定性仿真 + 不变量检查器,服务他人调策略 |
| 故障优势不显著 | 缩小主张到"配额隔离"单点,或承认负结果并关闭路线 |

## 6. 对现有仓库的处理

- 冻结新特性;保留现有测试与交付闸门,作为 P1/P2 的回归网
- `AlignedPolicy`、负结果实验保留(可复现),但不再扩展
- 文档只维护:设计规格、扩展指南、交付标准;新增内容一律走 PR 描述
- 本文件是唯一在册计划;旧 roadmap 标记为被取代

## 7. 不做的事(再次明确)

- 不做多机
- 不做引擎内核重写
- 不做"又一个 workflow-aware KV cache"论文复现
- 不为数字调参;负结果照写
